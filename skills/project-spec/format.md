# 기획명세서 작성 형식

기획명세서는 공문서 개조식으로 쓴다. 긴 문장을 표 칸에 몰아넣지 않고, 중요한 내용부터 단계를 나눠 짧게 쓴다.

이 문서가 형식의 기준이다. 문서는 어두운 화면 설정에서도 회색 바탕 위 흰 종이로 보인다. 글꼴, 크기, 색은 `template.html`에 있다. 장마다 무엇을 쓰는지는 `SKILL.md`를 따른다.

## 1. 단계와 글씨 크기

중요할수록 크게 쓴다. 크기는 단계로 정해지므로 HTML에 `style`이나 `font-size`를 쓰지 않는다.

| 중요도 | 단계 | 표시 | HTML | PC 크기 |
|---|---|---|---|---|
| 1 | 문서 제목 | 위아래 선, 가운데 | `<h1>` | 38px |
| 2 | 장 | 남색 번호 칸 | `<h2><span class="no">1</span>개요</h2>` | 26px |
| 3 | 주제 | □ | `<h3>` | 20px |
| 4 | 항목 | ○ | `ul.gae`의 `li` | 17.5px |
| 5 | 세부 | - | `li` 안쪽 `ul`의 `li`, 본문 `p` | 15.5px |
| 5 | 표 | 위 굵은 선, 세로줄 | `<table>` | 14.5px |
| 6 | 참고 | ※ | 항목 아래 `<p class="note">`, 항목 안 `<div class="note">` | 14px |

- □ ○ - ※ 기호는 CSS가 붙인다. 글자로 적지 않는다.
- 세부 아래로 내려가지 않는다. 더 나눠야 하면 항목을 나눈다.

## 2. 문장

- 항목과 세부는 `~함`, `~임`, `~음`, `~됨`이나 명사로 끝내고 마침표를 찍지 않는다. `~다`, `~습니다`는 쓰지 않는다.
- 줄 하나에 내용 하나만 쓴다. 두 줄을 넘으면 세부로 나눈다.
- 종류가 나뉘는 항목은 앞에 소제목을 붙인다: `<b>(핵심 기능)</b>`
- 결론과 중요한 내용을 먼저 쓴다. 근거와 단서는 뒤로 보낸다.
- 쉬운 말로 쓴다. 어려운 한자어, 외래어, 번역 투를 피하고 명사만 나열해 끊지 않는다. 약어는 풀어 쓰고 괄호에 원어를 둔다: 첫 판(MVP)
- 화면 문구와 사람의 말을 따온 글은 원문 그대로 둔다.

## 3. 표와 개조식 고르기

| 쓰는 때 | 형식 |
|---|---|
| 칸이 낱말, 숫자, 짧은 구절이고 줄끼리 비교한다 | 표 |
| 설명이 주인공이다. 칸에 문장이 둘 이상 들어간다 | 개조식 |

| 장 | 형식 |
|---|---|
| 기획 1장 개요 | 개조식. 표를 쓰지 않는다 |
| 기획 2장 용어 정의 | 낱말 위주의 표. 뜻 칸은 짧은 구절 하나 |
| 기획 5장 기능 명세 | 개조식. 표를 쓰지 않는다 |
| 그 밖의 장 | `SKILL.md`에 적힌 표. 칸은 짧게 쓴다 |

표 칸에는 문장 하나만 쓴다. 단서가 붙으면 칸에서 빼 표 아래 `<p class="note">`로 쓴다.

## 4. 임시안, 확인 필요, 반복

- 임시안과 확인 필요는 문장 사이에 섞지 않고 그 항목 끝의 ※ 줄로 쓴다.
  - `임시안: 주인 없는 칸은 훈련 부대를 이기면 차지함`
  - `확인 필요: 유지 기간(Q-42)`
- 묶음 안의 근거나 상태가 모두 같으면 묶음 맨 위 ※ 줄에 한 번만 쓰고 항목에서 뺀다. 다른 항목에만 따로 적는다.
- 근거(`파일:줄`)는 문장 뒤에 붙이지 않는다.
  - 기능 항목은 이름 옆 `<span class="ref">`에 쓴다.
  - 그 밖의 항목은 주제 끝 ※ 줄에 모은다: `근거: README.md:3, todo.py:1`
- 같은 설명을 장마다 되풀이하지 않고 번호로 가리킨다.

## 5. 붙임과 끝맺음

- 장 안에서 흐름을 끊는 긴 표(결정 기록, 검증 순서 등)는 장 끝에 접어 둔다: `<details class="fold"><summary>붙임 1. 제목</summary>…</details>`
- 긴 내용은 줄이지 않고 옮긴다. 채택되지 않은 내용은 붙임에도 옮기지 않고 지운다(`SKILL.md`의 지킬 규칙).
- 개발 편의 부록은 `붙임 A`, `붙임 B`로 쓴다.
- 편마다 맨 끝에 `<p class="end">끝.</p>`를 둔다.

## 6. 이동

- 번호는 글자로만 쓴다. `<a>`를 직접 쓰지 않아도 스크립트가 누를 수 있는 연결로 바꾼다.
- 번호의 자리는 표 첫 칸(`<td>F-01</td>`)이나 항목 이름(`<b>F-01 기능 이름</b>`)이다. 이 자리에 쓰지 않은 번호로는 이동할 수 없다.
- 표 첫 칸에는 번호만 쓴다.

## 7. 예시

고치기 전:

```html
<tr><td>F-01</td><td>작업 저장</td><td>사용자가 저장을 누르면 내용을 검사하고 저장한다. 제목은 100자까지다(P-01). 저장에 실패하면 다시 시도할지는 정하지 않았다(Q-01).</td><td>S-01</td></tr>
```

고친 뒤:

```html
<h3>작업 관리</h3>
<p class="note">이 묶음의 근거는 모두 <code>app/task.py</code>이고, 상태는 모두 완료임</p>
<ul class="gae">
<li><b>F-01 작업 저장</b><span class="ref">화면 S-01</span>
<ul><li>사용자가 저장을 누르면 내용을 검사하고 저장함</li><li>제목은 100자까지임(P-01)</li></ul>
<div class="note">확인 필요: 저장에 실패했을 때 다시 시도할지(Q-01)</div></li>
</ul>
```

## 8. 점검표

다 쓴 뒤 파일을 Grep으로 확인한다.

- `id="overview"` 장의 붙임 앞과 `id="features"` 장에 `<table`이 없다.
- 본문에 `다\.</(li|td|div|p)>`가 없다. 따온 글은 괜찮다.
- `<td>` 칸 하나에 마침표가 두 개 이상 없다.
- `id="terms"` 장의 뜻 칸에 마침표와 번호(`P-01` 등)가 없다.
- 진행 히스토리 밖에 `없앰`, `뺌`, `쓰지 않음`, `미룸`, `뒤로 미`, `후속 후보`, `(제외)`가 없다.
- `ul.gae`의 문장 뒤에 `<code>파일:줄</code>`이 없다. `.ref`와 `.note` 안은 괜찮다.
- `<style>` 밖에 `style=`과 `font-size`가 없다.
- 글자로 적은 □ ※가 없고, ○는 권한 표에만 있다.
- 장 제목이 모두 `<h2><span class="no">`로 시작한다.
- 편마다 `<p class="end">끝.</p>`가 있다.
